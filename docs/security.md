# Security: threat model

A one-page threat model for Bidwright as built at `v0.3`, with the controls planned for later iterations marked. Iteration 5 completes this document. The controls are mapped to the OWASP Top 10 for Agentic Applications (version 2026, published December 2025) and the OWASP Top 10 for LLM Applications 2025. Both lists were read at the source on 2026-11-02 (V-01 in [`verification_log.md`](verification_log.md)).

## Classification

**Medium as built:** Bidwright only drafts, runs on synthetic RFPs, and submits nothing. **High for a real deployment,** where RFPs are confidential and a missed requirement can disqualify a bid. The classification is self-assessed, because no defining standard was available to the project.

## Assets

| Asset | What a breach would mean |
|---|---|
| RFP content | Confidential in real use. Free-tier prompts may be used by the provider, so `free` takes only the synthetic corpus, unless a run passes the consent override, which its manifest records (ADR-026). |
| The requirement list and its quotes | A wrong or missing obligation can disqualify a bid |
| API keys | Spend and quota on the owner's accounts |
| The NotebookLM login | A cookie-based login on the owner's personal Google account, held by the NotebookLM server on the host, which can also delete and share the owner's notebooks |
| Gold labels | If a producer could read them, every score would be meaningless |
| Research packs | Committed web research that a run's appendix shows, and the library pack `techcheck` reads; a changed pack would change what every run in its domain reports, or which technology claims pass |
| The knowledge base | The supplier's capability evidence: a planted or changed record would let a claim pass `assess` |
| The gate's approval | The decision that lets a manifest be drafted from; a forged or stale approval would draft what nobody approved |
| Traces | Metadata about the documents processed |
| Run folders | The document's text and every record drawn from it |
| The UI and the API | Pages and endpoints on loopback that read run folders, start runs and decide gates through the CLI |

## Trust boundaries

1. **The RFP file to `ingest`:** document text is untrusted, and may carry instructions aimed at the model.
2. **The app to outside services:** on `free` and `paid`, prompts go to Gemini, whose paid tier logs prompts for a limited period but does not train on them, and `assess` and `techcheck`'s calls to Cerebras or Groq: one claim with the records and requirement statements it rests on, or one technology claim with its documentation; on `local`, nothing leaves the machine. Whole documents go only to the local Docling service, and spans only to a local collector or to `spans.jsonl`. The egress register checks every destination against the run's data class before the run starts (ADR-026).
3. **Model output to code:** every response is untrusted until it parses and passes its acceptance check ([`architecture.md`](architecture.md), section 5.4).
4. **An agent to its tools:** every call passes `ToolGateway`'s checks and rules before it runs.
5. **Producer to evaluation:** `src/bidwright` never imports `evals`, and only the `eval` service mounts gold.
6. **The supply chain:** Python packages, container images, CI actions, and the pinned NotebookLM server package.
7. **Documentation, from Iteration 3:** in research mode `live`, `techcheck` sends a library name and a question built from one technology claim to Context7's remote server, through the gateway's G3 and G4; its documentation comes back as untrusted text, screened like research, and a verdict must quote it. The egress register lists Context7 as remote, so a client run reaches it only through research mode `live`, which a client run is refused.
8. **People to the gate and the pages:** the approval comes from `bidwright approve`, run by a person or by the Review page, and the gate checks it against the hashes of what was reviewed; the UI and the API listen on loopback only (ADR-050, ADR-051).
9. **Research, from Iteration 2:** in research mode `live`, queries leave for Google through the NotebookLM server, and its reports, answers and excerpts come back as untrusted web data. The server runs on the host, bound to loopback, only during live sessions; the egress register treats it as remote whatever its host, so a client run with research mode `live` is refused before its folder exists, and a stdio server entry is refused on every run (section 4.5 of [`designs/iteration-2.md`](designs/iteration-2.md)).

## Run control

`RunSupervisor` (ADR-031) takes an exclusive lock on `control/run.lock` for each part of a run, records every status in the manifest and `events.jsonl`, and refuses a resume of a finished run, a run that predates `v0.2`, a run in `record` or `replay` mode, one started in another environment, one whose prompts or input files changed, and a profile change other than `free` to `paid` after a spent quota; a run waiting at the gate is refused a resume and continues only through `bidwright approve`. A resume cuts a line a kill left unfinished from each line file before appending to it. Locks taken on the host and in a container do not see each other on the bind-mounted `outputs/`, so a run records where it started and is resumed only there; a container run is resumed only after its container has exited.

## Evidence behind the design

Q-07 ([`context/Research-Register.md`](../context/Research-Register.md), section 7) found that prompt-layer defenses such as delimiters reduce indirect injection without removing it, and that the effect varies by model. Controls outside the model held where model decisions were manipulated. So delimiters stay as hygiene, and the weight sits on screening before parsing, the gateway, least privilege and `DRAFT_ONLY`. CrackedPDFs, confirmed at source, shows why screening must read the PDF's structure ([`evaluation.md`](evaluation.md)).

## Reviews at `v0.3`

A security review of the Iteration 3 changes (`v0.2` to the working tree) on 2026-11-10 found no vulnerability at high or medium confidence. It traced the UI's subprocesses and the run selection, the absence of HTML or Markdown rendering of document or model text, the API's Host allowlist and header rule, the knowledge base's parameterized SQL, every YAML load, the file names taken from model ids, the egress register's entries for Cerebras, Groq and Context7, span replay, the image and the CI change. Of its two notes below the threshold, the Phoenix key now goes only to the configured endpoint when spans are replayed to another, and the other is listed below. A code review at medium effort the same day raised ten findings; nine were fixed with tests (the commit of 2026-11-10 "fix the code review's and the security review's findings") and one kept as designed (ADR-046).

## Reviews at `v0.2`

A security review of the Iteration 2 changes (`v0.1` to `v0.2`) on 2026-11-05 found no vulnerability at high confidence. It traced file paths, the gateway's rules, deserialization, secrets and the research server as an untrusted party. It noted two weaknesses without a security impact, listed below. A code review at medium effort the same day raised ten findings, eight fixed before the tag (the commit of 2026-11-05 "fix the code review's findings"). ADR-038's filter and the drift report's three code fixes came after both reviews, each with its own test.

## Residual risks at `v0.3`

- `guard` reads a PDF's drawing operations, not the rendered page, so a font that maps glyphs to other characters escapes it ([`architecture.md`](architecture.md), section 11).
- The egress register treats `ollama`, `phoenix`, `docling` and `host.docker.internal` as local everywhere, though they name this machine only inside a container (D-06, deferred).
- The consent override lets a client document run on `free`, against the free tier's terms; the owner accepted that risk (ADR-026), and the manifest records each use.
- A paraphrased injection can still steer what an agent writes inside its schema; only measurement per model (QS-3) shows how often.
- G3 stops a copied passage, not a paraphrase: on the outbound test set it let through no verbatim copy, no lightly edited copy, and every paraphrase ([`evaluation.md`](evaluation.md)). Short identifying phrases in topics are not detected; a client run gets no live research.
- In research mode `live`, a source that reads like a published solicitation is left out before any excerpt is made, and an answer that cited one has its text withheld (ADR-038); a tender whose title and URL do not read that way still passes, and the job's own report, which has no per-source structure, is not filtered.
- A research pack's hashes sit in its own `pack.yaml`, so they catch a file that changed by accident, not a pack rewritten on purpose; packs change only by reviewed commits.
- Research items, needs and source titles are written into `solution_summary.md` without Markdown escaping; the summary is a draft read by people, and nothing acts on it.
- G2 refuses a run of 30 or more letters, digits, hyphens and underscores, so a long hyphenated phrase in a question is denied as an id, with a security event; this false positive is accepted by ADR-032.
- A `research_status` error result fails the job, since the server has no failed state, so one transient error sends a live run to its research pack.
- The NotebookLM login is a personal cookie session, acceptable for synthetic research only; the server also offers delete and share tools to any local client while it runs.
- CI actions are pinned by version tag, not by commit hash.
- The Streamlit UI has no Host check of its own, unlike the API: a page that rebinds a DNS name to 127.0.0.1 could reach it, start runs and decide a gate. It listens on loopback only, and browsers now ask before a site reaches the local network; a proxy with the API's Host allowlist would close it.
- The gate's role is free text that the person types; it names a role, not an authenticated identity, which suits one owner on one machine and not a team.
- `assess` sends a claim's knowledge-base records and its need's requirement statements to Cerebras or Groq. The egress register lists both as remote, so a client run is refused them, as it is every remote destination except Gemini under the consent override (ADR-026).
- Human review is subject to fatigue and automation bias, which DR-08 studies before the review interface is built.
